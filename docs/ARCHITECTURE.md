# Архитектура проекта

## Обзор

```
┌─────────────┐     ┌──────────────────┐     ┌──────────────┐
│  Пользователь │────▶│  Streamlit UI    │────▶│  GigaChat    │
│  (браузер)    │◀────│  (main.py)       │◀────│  API         │
└─────────────┘     └──────────────────┘     └──────────────┘
                           │
                           ▼
                    ┌──────────────────┐
                    │  gigachatapi.py  │
                    │  - Auth (OAuth)  │
                    │  - Retry逻辑     │
                    │  - Context trim  │
                    └──────────────────┘
```

## Модули

### `main.py` — UI-слой

Отвечает за отображение интерфейса чата в браузере через Streamlit.

**Обязанности:**
- Рендеринг сообщений с CSS-стилями
- Анимация набора текста
- Управление session state (история сообщений, токен)
- Сборка контекста для API-запроса

**Не зависит от:** деталей API-протокола, формата ответов GigaChat.

### `gigachatapi.py` — API-слой

Чистый API-клиент без привязки к Streamlit. Может использоваться из любого Python-кода.

**Обязанности:**
- OAuth-аутентификация (получение токена)
- Отправка текстовых запросов с контекстом
- Генерация изображений
- Retry с экспоненциальной задержкой
- Обрезка контекста по лимиту токенов

**Публичный API:**
| Функция | Назначение |
|---------|-----------|
| `get_access_token()` | Получить OAuth-токен |
| `send_prompt(messages, token)` | Отправить историю диалога |
| `generate_image(prompt, token)` | Сгенерировать изображение |
| `is_image_request(prompt)` | Проверить ключевые слова |

## Потоки данных

### Текстовый диалог

```
Пользователь вводит текст
        │
        ▼
main.py добавляет в session_state.messages
        │
        ▼
main.py собирает api_messages (system + история)
        │
        ▼
gigachatapi.send_prompt() обрезает контекст (_trim_messages)
        │
        ▼
POST /chat/completions с retry (3 попытки)
        │
        ▼
Ответ отображается с анимацией
```

### Генерация изображения

```
Пользователь вводит "нарисуй кота"
        │
        ▼
is_image_request() = True
        │
        ▼
generate_image() отправляет запрос с role="system" (художник)
        │
        ▼
Парсинг HTML-ответа → извлечение <img src="file_id">
        │
        ▼
GET /files/{file_id}/content → PIL.Image
        │
        ▼
Отображение в чате
```

## Retry-логика

```
Попытка 1 → ошибка (5xx / 429 / timeout)
    │
    ▼ ждём 1с
Попытка 2 → ошибка
    │
    ▼ ждём 2с
Попытка 3 → ошибка
    │
    ▼
Возвращаем None, логируем ошибку
```

Повторяем только на:
- HTTP 500–599 (ошибки сервера)
- HTTP 429 (rate limit)
- ConnectionError / Timeout

Не повторяем на:
- HTTP 400–499 (ошибки клиента)
- JSON decode errors

## Ограничение контекста

Максимум 4000 токенов (~16 000 символов). Алгоритм `_trim_messages`:
1. Идёт с конца истории
2. Суммирует длины сообщений
3. Останавливается, когда превышен лимит
4. Возвращает обрезанную историю в исходном порядке

Системное сообщение (`role="system"`) добавляется отдельно и не входит в лимит.
